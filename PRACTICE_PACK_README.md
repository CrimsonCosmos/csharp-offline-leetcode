# C# LeetCode Mediums: Offline Practice Pack (with test suites)

1,413 Medium problems with C# starter code. **1,259 of them have an automated test suite** (about 121,000 test cases in total, a median of about 99 per problem). Everything runs offline once you have the .NET SDK.

## Quick start

Requires the **.NET 8 SDK or newer** (https://dotnet.microsoft.com/download).

1. Open a problem's `Solution.cs`, e.g. `problems/0002-add-two-numbers/Solution.cs`, and write your solution in it. (Read `README.md` in the same folder for the statement.)
2. Run it against the tests:

```bash
./run.sh 2                      # macOS / Linux / Git Bash
.\run.ps1 2                     # Windows PowerShell
```

You can use the problem number or part of the name (`./run.sh longest-substring`).

Example output:

```
PASS 0002-add-two-numbers: 59/59 tests passed (188 ms)
```

or, on a failure:

```
FAIL #3
  input:    s = "pwwkew"
  expected: 3
  got:      4
FAIL 0003-...: 54/69 tests passed (65 ms)
```

Options (add after the problem): `--unordered` (ignore the order of results), `--all` (show every failure, default is 3), `--stop` (stop at the first failure).

Without the scripts: `dotnet run --project Practice -p:Problem=<folder name> -- <full path to the problem folder>`.

## What's in each problem folder

- `README.md`: statement, examples, constraints, hints
- `Solution.cs`: the LeetCode C# starter. Edit this file.
- `tests.json`: test cases (`a` = arguments, `e` = expected)
- `EDITORIAL_SPOILERS.md`: editorial, if available (open it only when done)

`INDEX.md` lists every problem with its topics and how many tests it has. Search it for a topic like "Dynamic Programming".

`ListNode` and `TreeNode` are provided by the runner. Ignore the commented-out definitions at the top of some stubs. Keep the method name and signature from the stub.

## Things to know about the tests

- **They are not LeetCode's hidden tests.** Those are private. These come from the open LeetCodeDataset: inputs were generated by an LLM, and the expected outputs were produced by running reference solutions. They're good for catching wrong answers and edge cases, but a pass here doesn't guarantee a pass on leetcode.com.
- **Any-order answers:** some problems accept results in any order (permutations, subsets, group anagrams...). The expected output is one specific order, so a correct solution can fail. The runner tells you when failures only differ in order. Re-run with `--unordered`.
- **Problems with several valid answers** (not just different order) can't be checked this way; a correct answer may be marked wrong.
- **In-place problems** (11 of them, e.g. Rotate Image) have tests that only check your code runs without crashing, because the dataset doesn't store the modified result. Verify those with the README examples.
- **Skipped tests:** a few generated tests have inputs that can't exist on LeetCode (e.g. a decimal inside a tree). The runner skips them and says how many.
- 154 problems have no tests (marked `none` in `INDEX.md`). Use the README examples for those.
- Each test has a 10-second timeout.
